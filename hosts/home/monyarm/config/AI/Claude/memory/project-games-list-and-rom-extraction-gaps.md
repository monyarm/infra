Extraction **verified 2026-11-16** (manifest pull + depot 229481 download, not just a guess):
- Content is an Iron Galaxy "Mana" native wrapper (`ManaGame.exe`) over real CPS2 emulation, not a reimplementation. ROMs sit in `data/zip/ddsom_essentials.wad.zip` and `data/zip/ddtod_essentials.wad.zip`, each holding `roms/main.rom` + `roms/gfx.rom`.
- **Program ROMs come out byte-exactly.** `main.rom[0:0x400000]` is the CPS2 program region; split into 8 × 0x80000 and byte-swap each 16-bit word (inverse of MAME `ROM_LOAD16_WORD_SWAP`) → all 13 CRCs match MAME: ddsom 8/8 (`dd2e.03e` 449361af … `dd2e.10` e198805e), ddtod 5/5 (`dade.03c` 8e73533d … `dade.05c` ea996008). They ship the *encrypted* originals, de-interleaved into CPU-region order.
- **GFX does not come out**: `gfx.rom` is already MAME's region size (0x1800000 for ddsom) but no tried de-interleave (64-bit word interleave across 4 chips, plain concat, 16/32-bit swaps, concat-split 4×4MB+4×2MB) reproduces `dd2.*13m–20m`; it is stored swizzled/decrypted for the PC renderer.
- **QSound samples do not come out** either: the trailing 4 MB of `main.rom` matches nothing under simple transforms, and the LC re-authored audio into `data/sound/soundbanks/{SOM,TOD}_Common.sb`.
- **The 20-byte `ddsom.key`/`ddtod.key` is not shipped as a file** — it must live inside `ManaGame.exe`.
- Verdict: program-extractable, but **not a complete MAME set** today; gfx swizzle reversal + key recovery is an open-ended RE detour, not a packaging job.

**Settled 2026-11-16: the four owned Capcom collections are native ports, not emulated ROMs — nothing is extractable, so no new emulation entries/NDS system should be added:**
- Castlevania Dominus (2369900): only `windata/alldata.bin` (mdf\0, 1.28 GB) + `alldata.psb.m`; MArchive unpack key differs from ours (`MArchiveBatchTool fullunpack --keep alldata.psb.m zlib "Illegal function call" 92`) but the output has no ROM files. RED-Project #174 and a Steam guide state explicitly that no ROMs can be extracted; M2 made a native remaster reusing converted assets. This overturns the earlier guess that Dominus was a cheap win via `marchiveUnpack`.
- Mega Man Zero/ZX Legacy (999020): no `.gba`/`.nds` among the 12,029 depot files and **no GBA cartridge header anywhere** (no `24 FF AE 51 69 9A A2 21`, no `AGB`/`NDS` game-code field, no BIOS in `MZZXLC.exe`; earlier `.bin` "AGB" hits were bytes inside compressed bitstreams). `nativePCx64/RZZC/romPC` is 914 MB / 199 files of *new* assets only — `{Z1..Z4,ZX,ZXA}SE.arc` sound-effects archives (MT-Framework `ARC\0`), `*_HDTexure.arc`, `Gallery/*/ImgTex_Near.arc`, `{Option,Title,Music,Manual,Language,Credit,Gallery,TrophyPopup,Achievement}UI.arc`, `Font_*.arc`, `ZXModel.arc`. The game data itself is LZ77Wii chunk containers (`ZC/DATA`, `ZX/DATA`, `ZXA/DATA`, ~156 MB compressed, per-asset files like `boot_z1.bin`), with **no** filenames/addresses in them. `ZX/DATA/zero3.bin` (4.58 MB) and `zero4.bin` (7.59 MB) are interleaved **relocation tables** (runs of `0x083A0E00`… / `0x088A7344`…, the latter past 8 MiB so the address space was expanded) beside entropy-6.5 payload — these are the only genuinely ROM-address-keyed data. Anything that looks like an 8 MB+ blob is a `.wmv` movie or a `*SE.arc`. **Retracted:** the earlier claim that `boot_z3/z4.bin` hold "genuine GBA ROM addresses" — those are container offsets with bit 31 set (the compression flag), not pointers. Verdict: provenance is GBA/DS-era game data, but the ARM code is not shipped and runs natively as x86; rebuilding a cartridge is an RE project, not packaging.
- Mega Man X Legacy Collection 2 (743900): native `.arc`/`.sngw`/`.xsew` per game (X5–X8), movies dominate; no disc images. **X4 is native** (matches the repo comment in `Emulation/snes/mmxlc.nix`) — depot 743891 has `nativeDX10/X4/romPC/pl00.arc`, reusing the 1998 PC assets.
- Mega Man Legacy Collection 2 (495050): `disc` is a 1.42 GB **ZIP** (ZipCrypto, stored, 2161 entries) of native `rm07`–`rm10` asset trees, not a CD image; `res00x` are LZ-compressed `.womv` movies; `MMLC2.exe` carries PS1 directory names (`STAGE00.BIN`, `SLES_010.64`) only as native-port data. No MM7 SNES ROM.
