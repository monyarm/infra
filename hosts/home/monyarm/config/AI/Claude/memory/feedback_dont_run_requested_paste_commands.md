## name: dont-run-requested-paste-commands description: "When the user asks for a command/one-liner "to paste" or "so I can run it myself", hand it over as text — don't execute it (not even --dry-run)." metadata: node_type: memory type: feedback originSessionId: d24c4aa1-6d5f-4fe7-98d1-668cb8eef1f1

When the user explicitly asks for a command they intend to run themselves (e.g. "give me a one-liner", "so I can run it myself", "tell me the store path so I can run switch myself"), do not execute that command — not even in a safe/dry-run form. Just output it as text for them to copy.

**Why:** In the ~/.nix session, the user asked for a bash one-liner to build a filtered set of WAD derivations "so I can get them out of the way quicker." When the one-liner was reworked into a `linkFarm`-based single build, it was run via `nix build --dry-run` to sanity-check it before handing it over. The user reacted sharply: "WHY DID YOU TRY TO BUILD IT YOURSELF!? I WANTED A ONELINER TO PASTE." The request to hand over a runnable command is itself a signal they want to run it themselves (possibly on a different machine, at a different time, or just because they asked) — testing it preemptively, even harmlessly, is not what was asked and reads as not listening.

**How to apply:** When a request is phrased as "give me X to run/paste" (as opposed to "do X" or "build X"), treat that as an instruction to produce text, not to invoke tools against the real system. If verification is genuinely needed, either ask first, or verify a narrower/cheaper sub-piece that doesn't touch the actual target of the command (e.g. checking that referenced attribute paths/names exist via a separate, smaller eval), and say explicitly what was and wasn't verified.

**Recurred once already** (same ~/.nix project, later session): user pasted their own working `nix build` one-liner and said "Here's what I'm calling: it'd be best if we can just have it auto exclude the last 2, and run a nix build with all the rest" — this reads as describing what the *script* should do, and handing over their own command as the starting point to adapt, not as blanket permission to execute. Misread it as "go ahead and run it" and did. Reaction: "What do you think you're doing? I just wanted you to give me the script, not run it." The tell in hindsight: they'd already been the one manually running every build command themselves throughout this whole conversation (the ad-hoc pk3/pk7 test builds, the `--append` re-runs) — a user with that established pattern describing a script's desired behavior is not the same as asking me to execute it. Default to text-only unless they say "run it" / "go ahead" explicitly, even when a request is phrased declaratively ("I'm calling...") rather than as a question.
