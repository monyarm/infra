# Repository Instructions

## Shape

- This is a single Nix flake for Home Manager, NixOS, and `system-manager`; the wiring is in `hosts/default.nix`, not in a package-manager workspace.
- Configuration names are generated from directory names: `homeConfigurations.monyarm`, `nixosConfigurations.gaming-laptop`, and `systemConfigs.gentoo-system`; the primary target is `nixosConfigurations.gaming-laptop`.
- Home Manager imports `hosts/home/monyarm/config` and `games` through `autoImport`; a new `.nix` module must be staged before `builtins.getFlake`/flake evaluation can see it.
- Shared custom helpers are assembled in `lib/default.nix`; package definitions under `packages/` are imported at two overlay sites, so new `callPackage` arguments may need threading through both `flake.nix` and `hosts/default.nix`/`lib/optimize/overlays.nix`.

## Commands

- Format with `nix fmt` or `nix fmt -- <file>`; `flake.nix` configures treefmt with nixfmt, deadnix, statix, mdformat/mdsh, prettier, shellcheck/shfmt, Ruff/isort/mypy, and other formatters.
- Validate the flake with `nix flake check`; this includes the derivation check for the filtered package output.
- Do not run Home Manager activation or `./stow.sh`.
- Build the primary system with `nix build .#nixosConfigurations.gaming-laptop.config.system.build.toplevel`; do not activate it as part of verification.
- `./deploy.sh <hostname> [remote_ip]` formats, stages all changes, and runs `nh os switch`; do not invoke it casually because it activates configuration and can target a remote host.
- `system-manager` is deprecated; do not introduce new usage. `./system.sh` is an existing privileged activation path for `.#systemConfigs.gentoo-system`, not a routine verification command.
- Use `./build-retry.sh <build-command> [args...]` for flaky network/remote-builder builds. For repeated fixed-output builds, resolve each derivation inside the retried command so hash corrections are picked up.
- Do not run `measure-compression.py` unless explicitly asked; when asked, use it for one game only.
- Update tracked external source metadata with `update-sources.py --append`; prefer its existing prefetch scripts under `scripts/prefetch/` for fixed-output hash discovery.
- Never run `git restore`, `git checkout`, or `git reset` on uncommitted work as a recovery shortcut; the index is not a backup, and user changes must be preserved. Do not edit autogenerated `sources.nix` directly.

## Nix Hazards

- Never run `ls`, `find`, `du`, `glob`, or `grep` recursively across `/nix/store` or `/`; resolve exact store paths through Nix instead.
- Do not pipe `nix build`/`nix eval` output through `head`/`tail` or wrap it in `timeout`; these hide diagnostics and progress.
- Evaluation is RAM-heavy on this machine. Before `nix build`, `nix eval`, or `nix-instantiate`, check for another `nix` process with `pgrep -x nix`; do not run competing evaluations.
- This flake evaluates secrets through `sops` using impure evaluation. Keep plaintext secrets out of changes and use `--impure` where the existing command requires it; `.env` and most lock files are ignored, while `flake.lock` is tracked.
- The optimization/compression pipeline uses experimental dynamic derivations (`builtins.outputOf`). Build one bare target at a time; a multi-target `nix build --expr` can silently do nothing, and narrowed subpaths may require building the parent placeholder instead.
- Do not reintroduce eval-time file reads/IFD for dynamic pipeline work. Dynamic derivation stages must remain primitive `derivation {}` values, not `stdenv.mkDerivation`; raw dynamic builders have no automatic `PATH`.
- Do not use `builtins.readFile` on a derivation output at evaluation time; perform checks that require realized files at build time instead.
- For performance investigations, compare before/after evaluations with `NIX_SHOW_STATS` and `--option trace-function-calls true`; the repository's recorded profiling conclusions are in `TODO.md`. Do not infer a regression from a formatted deploy versus an unformatted build: deployment scripts run whole-repo `nix fmt` first.
